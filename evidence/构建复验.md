## 3. 码流逐字节比对

两个 `.fs` 都是 7,264,153 字节，逐字节比较：

```text
diff bytes: 4
first: 543   last: 549
  @543  A='//Created Time: Tue Nov  3 13:54:24 2026'
  @549  B='//Created Time: Tue Nov  3 11:30:21 2026'
payload after byte 2048 identical: True
```

**结论：除文件头里的构建时间戳（4 个字节）外，两个码流逐字节完全一致。**

（SHA256 不同是因为那 4 个字节；配置数据本身相同，这与 `CheckSum: 0x6A6F` 相等互为印证。）

## 4. 复现方法

```powershell
cd LQR_Furuta_v1.1
& 'D:\Gowin\Gowin_V1.9.12.04_x64\IDE\bin\gw_sh.exe' build.tcl
# 检查 impl\pnr\LQR_end.fs 头部：//CheckSum 应为 0x6A6F
```

⚠ `build.tcl` 必须是 **UTF-8 无 BOM**。本次改名时第一次构建就踩了这个坑，
`gw_sh` 报 `invalid command name "??pen_project"` —— 见 [../docs/05_编码约定.md](../docs/05_编码约定.md)。
